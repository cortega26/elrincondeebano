# Content Manager (TypeScript)

Canonical admin application for product, category, storefront, media, import,
conflict, history, and publication workflows. Fastify + React + Vite on
TypeScript 7. Declared canonical in `AGENTS.md`; the Python/Tkinter fallback
was retired on 2026-08-11 (plan 069, rollback boundary: tag
`v1.x-python-final`).

## Run

From the repo root:

```bash
npm run admin:dev      # API dev server (:3000, tsx --watch — reinicia en cambios de src/server)
npm run admin:dev:web  # SPA dev server (Vite :5173, HMR — proxy /api a :3000). Plan 124.
npm run admin:start    # production server (serves dist/web if built)
npm run admin:validate # typecheck + test + build + parity
npm run admin:test     # vitest suite (contract + integration)
npm run admin:typecheck
```

## Modes

- `ADMIN_MODE=operator` — writes enabled; mutations require the launch
  credential.
- `ADMIN_MODE=read-only` (default) — every mutation is rejected with `405
READ_ONLY`, including handler-level guards (e.g. backup restore).

The server refuses to bind a non-loopback `HOST` and rejects requests whose
`Host` header is not `localhost` / `127.0.0.1` / `[::1]` (DNS-rebinding
protection, plan 071).

### OCI remote mode (behind an authenticated Cloudflare Tunnel)

Set `ADMIN_REMOTE_ORIGIN=https://admin.elrincondeebano.com` **only** on the
OCI instance, leaving `HOST=127.0.0.1`. The hostname is added to the
Host allowlist, browser mutations validate the HTTPS Origin, and **every
API read and write requires `x-admin-credential`**, including requests whose
source is loopback (the tunnel itself is local). Other hosts stay forbidden.

**Cloudflare Access must have a deny-by-default policy before adding the
hostname ingress/DNS route.** A tunnel alone does not provide user auth. This
setting is not an authorization to open port 3000 on the public firewall.
Use an independently generated, mode-0600 credential on the VM, not a token
from Pogo-lab or Fintual Executor.

Remote deployments must have a dedicated writable GitHub deploy key for the
`elrincondeebano` repo before the Publish button can push to GitHub. Without
one, local modifications must not be misrepresented as storefront releases.


## Launch credential

The credential is **never served over HTTP** (plan 071). Either:

1. Set `ADMIN_CREDENTIAL` (recommended for scripts), or
2. Start in operator mode without it — a credential is generated and written
   to `data/.admin-credential` (0600, gitignored; plan 125/127).

The web UI prompts for the credential on first use (`CredentialPrompt`);
mutations without it are rejected with `401`.

## What it writes

The manager writes the authoritative catalog files in `REPO_ROOT`:

- `data/product_data.json`
- `data/category_registry.json` (+ `data/categories.json` compatibility form)
- `astro-poc/src/data/storefront-experience.json` (storefront curation)
- backup snapshots under `data/backups/`

`astro-poc/src/data/products.json` and `public/data/product_data.json` are
**build-synced copies** generated by `astro-poc/scripts/sync-data.mjs` — do
not edit them directly.

## Tests

- `test/contract/` — unit tests, including the route-policy guarantee that
  every registered mutation route requires the launch credential
  (`routePolicy.test.ts`).
- `test/integration/` — `app.inject` suites against a real temp repo.
- `test/browser/` — Playwright keyboard/a11y specs; `test/e2e/` smoke specs
  (the harnesses serve the locally built `dist/web` — run `npm run build:web`
  first, or failures may reflect a stale bundle, not the source).
